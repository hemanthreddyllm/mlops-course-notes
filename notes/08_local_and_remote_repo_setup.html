Beyond the video · why ML repos ignore data and models

Git is built for small text files. Datasets and .pkl/.pt models are large binaries that bloat the history forever, and GitHub rejects files over 100 MB. Track them with DVC (Chapter 11) instead. Git then stores only a tiny .dvc pointer file. Also ignore secrets (.env, *.pem): if one is ever pushed, rotate the key, because deleting it in a later commit leaves it in the history.

07Cloning the repo to your machine 02:10:30

  1. On the repo page, click the green Code button, make sure HTTPS is selected, and copy the URL.
  2. Open the local folder where you keep projects.
  3. Open a terminal there: in Windows Explorer, right-click → Show more options → Open Git Bash here, or use your terminal.
  4. Type git clone, paste the URL (right-click pastes in Git Bash), and press Enter.
Git Bash · ~/projects
$ git clone https://github.com/<you>/github-learning-test.git
Cloning into 'github-learning-test'...

Receiving objects: 100% (5/5), done.
$ cd github-learning-test
$ clear
$ ls -a
.  ..  .git  .gitignore  LICENSE  README.md
$ code .                       # open this folder in VS Code

08What you get: the hidden .git folder 02:11:34

The cloned folder contains .gitignore, LICENSE, README.md and a .git folder that Git created. Git uses .git to track all changes. It is the version-control database. You don't need to understand what's inside it yet.

Can't see .git?

It's a hidden folder (it starts with a dot, as covered in Chapter 06). In Windows Explorer: View → Show → Hidden items. In a terminal: ls -a. On macOS Finder: Cmd+Shift+.

09Opening the project in VS Code 02:12:38

Move into the cloned folder with cd github-learning-test (the terminal shows you're inside it), clear the screen, and open the folder in VS Code, the editor most people use. The next chapter continues from here: write code, then commit and push it.

Tip

code . opens the current folder in VS Code if the code command is installed (in VS Code: Command Palette → Shell Command: Install 'code' command in PATH on macOS; on Windows it's added automatically). The Source Control panel (Ctrl+Shift+G) shows the Git changes visually.

11Interview questions

What is a .gitignore, and what should an ML project put in it?

A file listing path patterns Git should not track. For ML: Python clutter (__pycache__/, *.pyc, .venv/), notebook checkpoints, logs, secrets (.env, *.pem, credentials), raw and processed data, model binaries (*.pkl, *.pt), and experiment output (mlruns/, artifacts/). Data and models are versioned with DVC or a model registry instead.

git clone vs downloading the ZIP vs forking?

Clone gives you a working repository with full history and a configured remote, so you can commit, pull and push. A ZIP download is just the files, with no history and no link to the remote. A fork is a copy of the repository under your GitHub account (server-side), which you then clone.

What is the .git directory?

Git's database for the project: all objects (snapshots), refs (branches and tags), HEAD and config (including remotes). The working files are just a checkout of one version from it. Removing .git removes all version history.

Public or private repo for a company ML project? And how do you handle secrets?

Private, with access given to specific collaborators or teams. Either way, secrets never go in the repo. Use environment variables, a secrets manager (for example AWS Secrets Manager), or CI secrets such as GitHub Actions secrets, and keep .env in .gitignore. If a secret leaks, rotate it immediately.

You accidentally committed a 2 GB dataset. What now?

If it isn't pushed yet: git rm --cached the file, add it to .gitignore, and amend the commit. If it's already pushed, rewrite the history (for example with git filter-repo) and force-push after coordinating with the team, then track the data with DVC. GitHub blocks files over 100 MB anyway.

HTTPS vs SSH for Git remotes?

HTTPS authenticates with a token or credential manager and works through most firewalls. SSH authenticates with a key pair, needs no token prompts, and is common on servers and CI machines. Both give the same repository access.

12Recap

  • Confirm Git is installed: open Git Bash (Windows) or any terminal.
  • GitHub → New → name it after the project → Public/Private → ☑ README → .gitignore: Python → License: MIT → Create repository.
  • README = the project description on its page. .gitignore = files that won't be pushed. License = how others may reuse the code.
  • Code → HTTPS → copy → in your folder run git clone <url>.
  • The clone contains the files plus a hidden .git folder that tracks every change (turn on hidden items to see it).
  • cd into the folder and open it in VS Code. Next: writing code, then committing and pushing it.

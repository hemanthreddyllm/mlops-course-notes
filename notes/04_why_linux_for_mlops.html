Chapter 04 · Why Linux for MLOps

Why production ML runs on Linux

Linux is the first hands-on topic in the course. The reason is simple: the ML frameworks you use are built on Linux first, the cloud machines you deploy to almost always run Linux, and those machines have no graphical interface. You manage them entirely from a terminal.

01Where this fits: the Linux series 01:14:11

The instructor calls Linux the very first concept inside MLOps. The series has three parts:

This chapter answers one question: if I'm starting with MLOps, why learn Linux first? The sections below cover the five reasons the instructor gives.

02What Linux is: OS, kernel, distributions 01:15:17

Linux is an operating system (OS), like Windows or macOS. The instructor stresses that it isn't a single product: it comes in many distributions ("distros"). Each distro packages Linux with its own tools and defaults for a particular kind of work.

MOST RELEVANT TO US

Ubuntu

The most widely used distro in data science and AI, and common for general software development too. Most ML tooling is set up and tested for it. It is also the default Linux image on EC2 in this course.

SECURITY

Kali

Used for ethical hacking. Security and penetration-testing tools come built in, so you don't have to install them yourself.

SERVERS

CentOS

A server-oriented distro from the Red Hat family, common in enterprise data centres.

MINIMAL

Alpine

A very small distro. You'll meet it again as a lightweight Docker base image.

The point is that each distro has its own advantages and built-in functionality, so you pick one to suit the job. For AI and MLOps, that is usually Ubuntu.

Consider the libraries you use in each area of data science:

All of these are optimized for Linux. The instructor explains why: researchers build and test new frameworks on Linux, publish them, and only afterwards does the community port and optimize them for Windows and macOS. The original work happens on Linux.

04Reason 2: open source and customizable 01:18:25

Linux
  • Fully open source: the source code is public, so you can search for it online and change anything.
  • Even the kernel can be customized.
  • Many people contribute new features, which is why it keeps getting more popular and more powerful.
Windows / macOS
  • Closed source.
  • You get some customization options, but you can't change the OS as a whole.
Instructor's summary

Linux is "more powerful" for software development and AI because it's fully customizable, community-driven, and it's where frameworks and toolkits are implemented first.

05Reason 3: setup just works (the CUDA example) 01:19:27

Because packages are built for Linux first, installation errors are rare on Linux and much more common on Windows and Mac.

The instructor's example is setting up an NVIDIA GPU with CUDA for deep learning. Most people have run into this:

On Windows

Hard to install. It takes many configuration steps, and version mismatches can break it.

On Linux

You run a few commands and they install everything for you.

Beyond the video · what "a few commands" looks like on Ubuntu
ubuntu@gpu-server: ~
$ sudo apt update
$ sudo ubuntu-drivers install     # picks and installs the right NVIDIA driver
$ sudo reboot
$ nvidia-smi                      # shows the GPU, driver and CUDA version
$ pip install torch               # Linux wheels bundle the CUDA runtime
$ python -c "import torch; print(torch.cuda.is_available())"
True

Cloud providers also offer ready-made "Deep Learning" Ubuntu images with all of this pre-installed.

What is a virtual machine? 01:21:36

To run anything in the cloud you rent a virtual machine (VM). The instructor describes it simply: a VM is just a computer, a virtual one. It has RAM, CPU and GPU, the same hardware your own computer has, because your project needs a computer to run on. The cloud provider gives you access to that virtual computer so you can run your application there.

On AWS the VM service is EC2, which is what the next chapter sets up.

07Why not Windows on the server? 01:22:38

Most cloud VMs run a Linux-based OS such as Ubuntu. Windows images do exist in the cloud, and OSes are offered as an "image" (explained properly in the Docker chapter). Windows has two drawbacks on a server:

  1. It's a big image. It needs more space, so it costs more.
  2. Setup is harder. Packages are optimized for Linux, so on Windows you install extra tools, hit more errors, and have to fix things again when packages update. On Linux, the instructor says, "Linux by default takes care of everything."
The rule the instructor gives

Development: use any OS you like (Windows, Mac), it's completely fine.
Production: you work with Linux, so you must be comfortable with it.

08Reason 5: no GUI, only a terminal 01:24:44

"Linux is all about commands." On a cloud Linux server there is no user interface to click through the way you do on Windows. You get one black terminal and do everything from the command line:

🖱 Desktop OS (what you're used to)

Click to open folders, right-click to delete, double-click to edit files, use installer wizards.

⌨ Linux server (production)

Type commands to create and delete folders, write code, install packages and start your app.

ubuntu@ip-172-31-5-20: ~ (a fresh EC2 server)
$ mkdir cricket-forecast        # create a folder
$ cd cricket-forecast           # go into it
$ nano app.py                   # write code in a terminal editor
$ ls                            # list files
app.py
$ rm -r old-folder              # delete a folder
$ sudo apt install -y python3-pip   # set up software

09How this connects to serving your model

Beyond the video · the production path, seen through Linux
  • SSH: you reach the EC2 server from your laptop with ssh -i key.pem ubuntu@<public-ip>. That terminal is your only way in.
  • Docker is Linux too. The python:3.11-slim base image in Chapter 03's Dockerfile is Debian Linux. Even on a Mac or Windows laptop, Docker Desktop runs a small Linux VM underneath, so your container is "Linux in production" wherever it runs.
  • Kubernetes, Jenkins, CI runners (GitHub Actions' ubuntu-latest) all run on Linux. The commands you learn here are the same ones inside Dockerfiles and CI YAML files.
  • Debugging production means reading logs (tail -f), checking processes (ps, top), ports (ss -tulpn), disk (df -h) and GPUs (nvidia-smi), all from the terminal.

10Interview questions

Why is Linux preferred for deploying ML models?

(1) ML/DL frameworks (scikit-learn, TensorFlow, PyTorch, LangChain) are developed and tested on Linux first, so they install cleanly and run best there. (2) GPU/CUDA setup is much simpler. (3) It's open source and customizable, down to the kernel. (4) Cloud VMs, containers, Kubernetes and CI runners are overwhelmingly Linux. (5) Linux images are small and have no licence fee, so they cost less than Windows.

What is a Linux distribution? Which would you use for ML and why?

A distro bundles the Linux kernel with system tools, a package manager and defaults for a purpose. Examples: Ubuntu (data science/AI, general development), Kali (security), CentOS/RHEL (enterprise servers), Alpine (minimal containers). For ML, Ubuntu, because most tooling, drivers and cloud images target it first.

What is the kernel?

The core of the OS that sits between hardware and software. It manages CPU scheduling, memory, files, networking and device drivers (including GPUs). Linux's kernel is open source, so anyone can read and modify it.

What's the difference between a development server and a production server?

Development is your local machine (localhost), where only you access the app and any OS is fine. Production is a cloud virtual machine (AWS/GCP/Azure) that real users reach over the network with requests and responses. In practice it runs Linux and is managed through a terminal.

What is a virtual machine?

A virtual computer carved out of a cloud provider's physical hardware. It has its own CPU, RAM, GPU, disk and OS, and you rent it to run your application. On AWS the service is EC2.

Can you deploy on Windows servers? Why do teams usually avoid it for ML?

Yes, Windows images exist. They're much larger (more storage and cost, slower pulls), carry licence fees, and ML packages need extra setup and break more often after updates. Linux avoids all of that.

How do you manage a server with no GUI?

Connect over SSH and use shell commands: navigate and manage files (cd, ls, mkdir, rm), edit code (nano/vim), install software (apt, pip), and manage processes and logs (ps, systemctl, tail). In MLOps, most of this is then automated with Docker and CI/CD.

11Recap

  • Linux is an OS with many distros: Ubuntu (AI/data science), Kali (hacking), CentOS, Alpine.
  • AI frameworks are built and tested on Linux first, then ported to Windows and Mac.
  • Linux is open source and customizable (even the kernel), with a large contributor community.
  • Setup is easier: CUDA/GPU takes a few commands on Linux and a lot of effort on Windows.
  • Development = any OS on your laptop. Production = a Linux VM in the cloud (AWS, GCP, Azure, Alibaba). A VM is a virtual computer with CPU, RAM and GPU.
  • Windows server images are bigger, cost more and are harder to set up.
  • Production Linux has no GUI, so everything is done with terminal commands. Those are the next chapters.

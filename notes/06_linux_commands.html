00The Linux folder layout

Before running any commands, it helps to know where you are. Linux has a single tree that starts at /. When you log in to EC2 you start in /home/ubuntu.

Correction

In the video, /home/ubuntu is called "the root directory". It is your home directory. The root of the filesystem is /, and /root is the home folder of the root user.

01sudo and package updates 01:32:00

A new cloud machine needs its package manager updated before you install anything, much like running Windows Update on a new laptop.

ubuntu@ip-172-31-5-20: ~
$ sudo apt update          # refresh the list of available packages
$ clear                    # wipe the screen
$ sudo apt-get update      # same job with the older tool

sudo = "run as administrator"

The Windows equivalent is Run as administrator. It runs a command with root (admin) permission. Installing software and changing system files need it.

apt and apt-get

Both are front ends to Ubuntu's package manager, and they download from the internet. apt is the newer, friendlier one for interactive use. apt-get is older and has stable output, so it's the one to use in scripts and Dockerfiles.

Clarification · update vs upgrade

apt update only refreshes the list of packages; it doesn't install new versions. To actually upgrade, run sudo apt upgrade -y. To install something: sudo apt install -y python3-pip.

05Running Python on the server 01:39:20

ubuntu@ip-172-31-5-20: ~
$ touch test.py
$ vim test.py            # i → print("hello") → Esc → :wq
$ cat test.py
print("hello")
$ python3 test.py        # run it; Ubuntu ships python3
hello

This is the same workflow you'll use to run a training script or start an API on a server: create or copy the code, check it with cat, then run it with python3.

06Copy, move, delete: cp, mv, rm 01:40:22

ubuntu@ip-172-31-5-20: ~
$ cp test.py bappy_test/     # copy: file now exists in BOTH places
$ ls bappy_test
test.py
$ mv test.py bappy_test/     # move: file leaves the current folder
$ ls
bappy.txt  bappy_test
$ cd bappy_test
$ rm test.py                 # delete the file (no recycle bin!)
Careful with rm

rm deletes permanently. rm -r folder deletes a folder and everything in it. Check with pwd and ls before running it, and be especially careful with sudo rm -rf.

07Getting help and watching processes: man, top 01:42:28

man ls: the manual

Shows the official guide for any command: what it does and every option. Useful when you're new to a command. Press q to quit (h for help). ls --help gives a shorter version.

top: the Task Manager

The Linux version of Windows Task Manager. It shows live CPU and memory use per process. Press Ctrl+C (or q) to exit. htop is a more readable alternative.

Presets:
ubuntu@ip-172-31-5-20: ~
$ ls -l bappy.txt
-rw-rw-r-- 1 ubuntu ubuntu 6 bappy.txt
$ chmod 700 bappy.txt
$ ls -l bappy.txt

Precision note

The video calls 700 "administrator access". More precisely, it gives the owner full read/write/execute and removes all access for group and others. It doesn't grant admin (root) rights, which come from sudo. Common real-world values: 755 for scripts, 644 for files, 400 for SSH keys, and chmod +x run.sh to make a script executable.

09Compression: tar and zip 01:47:49

This is the Linux version of "zip it up". The standard format is tar. The instructor first forgets to give the archive a name, which fails, then fixes it and later has to look up the extract flags. Here are the correct forms:

ubuntu@ip-172-31-5-20: ~
$ touch bappy.txt test.py
$ tar -cvf archive.tar test.py bappy.txt   # c=create v=verbose f=archive file name (comes right after f)
$ ls
archive.tar  bappy.txt  bappy_test  test.py
$ tar -xvf archive.tar                     # x=extract
test.py
bappy.txt
$ sudo apt install -y zip unzip            # zip may not be pre-installed
$ zip files.zip test.py bappy.txt          # archive name first, then the files
$ unzip files.zip

10Users: whoami, useradd, userdel 01:50:00

ubuntu@ip-172-31-5-20: ~
$ whoami                 # which user am I?
ubuntu
$ useradd bappy
useradd: Permission denied.     # the demo hits this: user management needs sudo
$ sudo useradd bappy     # create a user
$ sudo userdel bappy     # delete it

The instructor calls this not an important command for the course, since deployments are done as the default or root user.

Beyond the video · in real production

Running apps as root is discouraged: if the app is compromised, the attacker gets the whole machine. Teams usually run services under a dedicated low-privilege user and use sudo only for admin tasks. Docker images often add USER appuser for the same reason. Following the course's approach is fine while you learn.

14Practice: serve a tiny API from EC2

Beyond the video · put the commands to work

This combines Chapters 05 and 06 into a first "production" deployment. Use a t2.small or larger, and add an inbound rule for TCP 8000 to the security group.

ubuntu@ip-172-31-5-20: ~
$ sudo apt update && sudo apt install -y python3-venv
$ mkdir hello-api && cd hello-api
$ python3 -m venv .venv && source .venv/bin/activate
(.venv) $ pip install fastapi uvicorn
(.venv) $ vim app.py
#   from fastapi import FastAPI
#   app = FastAPI()
#   @app.get("/health")
#   def health(): return {"status": "ok"}
(.venv) $ nohup uvicorn app:app --host 0.0.0.0 --port 8000 > app.log 2>&1 &
(.venv) $ curl localhost:8000/health
{"status":"ok"}
(.venv) $ tail -f app.log          # watch requests arrive (Ctrl+C to stop watching)

Then open http://<public-ip>:8000/health in your browser, and try /docs as well. When you're finished: ps aux | grep uvicorn → kill <PID>, then terminate the instance.

15Interview questions

What does sudo do? What's the difference between apt update and apt upgrade?

sudo runs a single command with root privileges. apt update refreshes the package index (the list of available versions). apt upgrade actually installs newer versions of installed packages.

Explain chmod 755 and chmod 700.

Each digit is a sum of r=4, w=2, x=1 for owner, group and others. 755 means owner rwx, group r-x, others r-x, which is typical for scripts and directories. 700 means owner rwx and nobody else has any access. SSH private keys need 400 or 600, or ssh refuses to use them.

How do you find and kill a process that's hogging CPU or holding a port?

Use top or htop to see per-process CPU and memory, or ps aux | grep name to find a PID. For ports, sudo ss -tulpn | grep :8000. Then kill <PID>, or kill -9 <PID> if it won't stop.

How would you view the last lines of a log file continuously?

tail -f app.log, or tail -n 100 -f app.log to start with the last 100 lines. Combine with grep to filter, for example tail -f app.log | grep ERROR.

tar vs zip, and what does -czvf mean?

tar bundles files (and keeps Unix permissions). Adding gzip (-z) compresses the bundle. zip bundles and compresses in one format that's common on Windows. -czvf = create, gzip, verbose, file name follows. Extract with -xzvf.

What's the difference between cp and mv, and rmdir and rm -r?

cp duplicates (the original stays); mv relocates or renames (the original is gone). rmdir only removes empty directories; rm -r recursively deletes a directory and everything in it.

How do you keep a model server running after you close SSH?

For quick tests, nohup … & or a tmux/screen session. For real deployments, a systemd service (auto-restart, starts on boot) or, most commonly in MLOps, a Docker container run with --restart, or an orchestrator such as Kubernetes.

16Recap

  • First on a new server: sudo apt update. sudo means admin permission, and apt/apt-get are the package managers.
  • Navigate: ls, ls -al (hidden files start with a dot), pwd, cd, cd .., clear, ↑ and Tab.
  • Folders and files: mkdir, rmdir, touch, vim (i → Esc → :wq), cat, head, tail.
  • Run code: python3 file.py. Manage files: cp (copy), mv (move), rm (delete).
  • Help and monitoring: man, top.
  • Permissions: owner / group / others × r(4) w(2) x(1). Set them with chmod 700 file.
  • Archives: tar -cvf out.tar files / tar -xvf out.tar, and zip.
  • Users (not needed for the course): whoami, sudo useradd, sudo userdel. Also date and echo.
  • When you're finished, terminate the EC2 instance (Chapter 05).

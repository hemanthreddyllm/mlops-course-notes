# MLOps course notes — working agreement

This repo is a study archive for the 12-hour **Ultimate MLOps Full Course** (YouTube `w71RHxAWxaM`).
It contains hand-written HTML notes for every chapter plus runnable, already-executed hands-on projects.

**The owner is studying MLOps for interviews and to deploy/serve models in production.** The notes are meant to
replace watching the video: they cover everything the instructor says, with diagrams, tables and interactive widgets.

---

## Layout

| Path | What's in it |
|---|---|
| `notes/` | one HTML page per chapter (`01_…` – `23_…`), `index.html`, `todo_after_course.html`, shared `assets/` (CSS, JS, images) |
| `projects/chNN_*/` | the hands-on work for a chapter: notebooks (with outputs saved), scripts, configs |
| `projects/_tools/` | `build_chNN.py` generators that write the notebooks, plus result-injection scripts |
| `transcript/` | the full transcript, split per chapter (`chapters/NN_*.txt`) — **source material, never published** |
| `docs/` | `HANDOFF.md` (status + how to run everything), `memory/` (Claude memory export) |

Chapter numbers in `notes/` are **not** transcript file numbers. See `docs/HANDOFF.md` for the mapping.

## How the notes are built (follow this for any new or edited chapter)

1. **Read the chapter transcript first** (`transcript/chapters/NN_*.txt`) — cover everything the instructor says.
2. **Page structure:** crumbs → eyebrow → h1 → lede → meta chips → TOC → numbered `<h2>` sections with `<span class="ts">hh:mm:ss</span>`
   timestamps → precision notes → `id="hands-on"` section → interview questions (`<details class="qa">`) → recap → pager.
   Reuse `assets/notes.css` classes (`callout key|wrong|beyond`, `grid`, `card`, `table-wrap`, `handson`, `result`, `files`)
   and end with `<script src="assets/notes.js">`.
3. **Hands-on for any coding chapter:** build real, runnable files under `projects/chNN_*`, **execute them**
   (`jupyter nbconvert --to notebook --execute --inplace <nb>`) so outputs are saved, then summarise results in the
   page's "Hands-on files" section. Never claim a result that wasn't produced.
4. **Be honest about the instructor's mistakes.** Every page has a "Precision notes" section; deprecated APIs,
   security shortcuts and factual slips get flagged there. Mark my own additions as "Beyond the video".
5. **Offline stand-ins** when the owner's accounts aren't available: `moto` for AWS, a local `mlflow server` for
   DagsHub/EC2, a local bare git repo for GitHub, simulators for Kubernetes/GitHub Actions. Say plainly what was faked.
6. **Deferred steps go to the to-do page** (`notes/todo_after_course.html`): append items with **stable ids**
   (checkbox state is saved in localStorage) and mention the additions in the reply.
7. **Every chapter also updates:** `notes/index.html` (row + status), the previous chapter's pager link,
   `projects/README.md` (a row for the new project), and the to-do page.
8. **Render-check before reporting:** headless Chrome, look for JS errors and layout problems.

## Conventions

* Notebooks are generated by `projects/_tools/build_chNN.py` — **edit the generator, not the .ipynb**, then re-execute.
  A generator rewrites every notebook it owns, wiping outputs, so re-run all of them afterwards.
* Charts saved into `projects/chNN_*/reports/` are copied into `notes/assets/img/` by the inject scripts.
* British-ish plain English, short sentences, no filler. Tables and diagrams over prose where possible.

### This archive was built on macOS (Apple silicon). On Windows, expect:

| Thing | macOS (as committed) | Windows |
|---|---|---|
| Shell commands in notebooks | `pkill`, `xattr`, `bash -c` | use Git Bash/WSL, or replace with `taskkill`/`psutil` |
| Port 5000 | taken by AirPlay → APIs use **5001** | 5000 is free; the port choice still works |
| `projects/_tools/bin/` | `actionlint`, `kubeconform` (darwin-arm64) — **not committed** | re-download the windows build (see `docs/HANDOFF.md`) |
| Prometheus + Grafana (ch23) | auto-downloaded to `~/.cache/mlops-course-tools` | `stack.py` picks darwin/linux only — add a windows branch or use WSL |
| Chapter 18 toy runner | runs steps with `bash` | needs Git Bash or WSL |
| Headless Chrome screenshots | `/Applications/Google Chrome.app/...` | `C:\Program Files\Google\Chrome\Application\chrome.exe` |

Docker was never installed on the build machine, so every Docker step is written but skipped — those are the first
things to run for real on a machine that has Docker.

## Guardrails

* **Never commit** secrets, the `.venv`, generated data/models, or the tool binaries (see `.gitignore`).
* The repo is **private**; only `notes/` is published to GitHub Pages. Keep `transcript/` out of anything public.
* Don't add notes for Jenkins (ch19) or CircleCI (ch20) unless asked — those placeholders are deliberate.
